# ANIM.teamMM 引擎 sce 脚本格式说明

样本：《壁の向こうの妻の嬌声2》（ANIM.teamMM, 2016）`kabe2_sce.dat`（原版日文，经 GSecret 解密后 2,255,905 字节）。
方法：静态逆向 `kabetuma2_GPT.exe` 的脚本解释器（Ghidra/REA 反编译 `FUN_004374e0` + 汇编路径分析），再用解密后字节流做逐段平铺验证。南方版 sce 同法交叉验证通过。
工具：`re/anim_gsecret.py`（解密）、`re/sce_token.py`（签名表）、`re/sce_parse.py`（记录级解析器）、`re/sce_export.py` / `sce_disasm.py`（导出）。

## 1. 文件布局（解密后）

| 区域 | 偏移 | 内容 |
|---|---|---|
| 头部 | [0, 8) | 两个 u32：`labelTableOff`、`stringPoolOff`（本样本 477652 / 495502） |
| 代码区 | [8, labelTableOff) | 指令流（见 §3）。开头是初始化段：两次 Gosub 初始化例程、若干初始化记录、以及按 `@[17]` 分发的章节跳转表；第一个标签 `CheckMemory` 在 523 |
| 标签表 | [labelTableOff, stringPoolOff) | 条目 = `[asciiz 名称][u32 代码偏移]`，共 1064 条有效 + 1 条终止空条目。名称如 `000-000`、`001-010`、`Mem01`、`_SYSLABEL_00001`…、 `CheckMemory`、`SeWait` |
| 字符串池 | [stringPoolOff, EOF) | NUL 结尾字符串顺序排列（本样本 35,368 条，含末尾空项），CP932 编码。脚本中所有字符串引用都是**池下标**（u32）。0 号是系统串「設定していない値が選ばれました」。文本含 `＠[漢字:かな]` 注音标记 |

## 2. 加密（GSecretFile）

`[00 00 00 01][16 字节随机密钥（明文存放）][密文体]`。正文逐字节 XOR 循环密钥；每处理满 16 字节，用刚解出的明文字节（块内第 15 字节）低 3 位选 8 套加法公式之一更新密钥。解密器已实测（图像解出合法 PNG、剧本解出可读文本）。奥特曼版为「假头+明文」变体（其 exe 被 patch 跳过解密）。

## 3. 指令流语法

记录 = `[u8 opcode][操作数…]`，opcode 范围 0x02–0xDC，解释器内是一个大 switch（`FUN_004374e0`，派发在 0x43779c）。标签定义记录 `0x0A` 后跟内嵌 asciiz 名称（与标签表偏移互相对应）。

基本操作数类型：`1`=u8，`2`=u16，`4`=u32，`8`=f64（均为小端）。

**表达式 EXPR**（`FUN_0043e300` ReadValue + `FUN_0043e350` 解析器）：
`[u8 tag][…]` — tag 为 0x40（'@'，局部标志）或 0x41（'A'，全局标志）时，后跟 u16 标志下标（共 3 字节）；其余任何 tag（常见 0x43='C'）后跟 u32 立即数（共 5 字节）。

**复合/变长记录**：
- `T`（op 0x67/0x68 参数设置）：固定 `(u8 参数id, u32 值)` 后按 id 追加尾巴：id=0x28 → +5×u8；id=0x46 → +u32；id=0x47 → +4×u32；其它 id 无尾巴。
- `K`（op 0xB2/0xB3 栈命令组）：`EXPR 头` 后循环：`[u32 条目标记][u8 子op][子参数]`，条目标记 == 0xBC 时结束。子 op 参数：B4=(E,E,E,u8,E)，B5=无，B6=(E, u32 池下标, u32)，B7=(u32×4)，B8=(E,E,E)，BA=(u8, u16, u8 t, t==0x43 时 u32 否则 u16)，BB=(u16, u32)，未列出的子 op 无参数。
- `C`（op 0xC0/0xC8 选项 Select）：`[u8 个数 n][n × (u32 全局选项值, u32 文本池下标)]`。选项值全剧连续编号（本作 0–109）。Select 之后紧跟每个选项一段 case 结构：`[op 0xC9, u8 case 序号(1 起)][op 0x0B goto 该选项目的地][op 0x0B goto END]`，END 为全部 case 共同的汇合偏移（其后即下一场景）；本作 50 个 Select 全部符合此式（2026-10-28 实测修正：初版误记为「跳转目标」）。
- `D`（op 0xD6 文本块，本样本未出现）：循环读 u8 条目类型：0xD3 → (u32, u32, u16) 一行；0xD8 → u32（设定当前说话人）；0xD7 → 结束。

### 4.1 ParamSet（0x67/0x68）参数表

handler 把参数块 `[id, value, 尾巴…]` 交给 `FUN_00413ca0` 按 id 分发到效果构建器；各构建器**当场**把渲染命令入队（`FUN_0040AE10`/`FUN_0040FA70`），故参数作用于**紧邻的上一个画面变更**（流中形态：`[画面 op] 0x65 0x66 0x68`）。跳过/快进时解释器会把 value 改写为 10（`FUN_0043E490` 分支），属运行时行为、与存盘字节无关。

| id | 构建器 | 语义（实测） | 本作次数 / value 分布 |
|---|---|---|---|
| 1（及 0、未列 id） | `FUN_00414230` | 普通淡入淡出（命令 0x65 入队），value = 时长 ms | 1,578；600 主导，另 0/10/800/1000/2000 |
| 33 (0x21) | `FUN_00414F90` | 40 步扩张方块过渡（步尺寸 32×18 递增、步延迟 = value/40×步号） | 1；1000 |
| 34 (0x22) | `FUN_00414D90` | 32 条带过渡（命令型 0x40001080） | 340；恒 600 |
| 35 (0x23) | `FUN_00414B80` | 32 片旋转/放射过渡（步延迟 = (value>>6)×步号） | 135；600（1 次 300） |
| 40 (0x28) | `FUN_00413F40` | 颜色淡变：value = 时长 ms，尾巴 5 字节 = (R, G, B, 起始 alpha, 结束 alpha)（如 `FF FF FF 00 FF` = 渐入白闪、`FF FF FF FF 00` = 白闪淡出） | 16 |
| 70 (0x46) | `FUN_004141E0` | (value, 尾巴 u32)；尾巴在解释器侧按 /1000 转浮点 | 本作未出现 |
| 71 (0x47) | `FUN_004164E0` | 全图层（含 5 个 E-mote 槽）滤镜/色调效果，尾巴 4×u32 为参数；value=1 且尾巴全 1 时解释器走参数缓存清零复位分支 | 7 |

子系统 7（`FUN_00401110(7)`）：解释器每条记录执行前检查其状态，状态 ∈ {0xB, 0xC, 0xE} 时暂停推进（`param_2` 调试模式除外）——0x68 执行后置 0xB 即「过渡进行中，脚本等待」。0x58（无操作数，169 次）亦置 0xB，常跟在 0x57 之后。

## 6. 验证结果

- 原版 sce：标签界定的 960 个代码段**全部逐字节精确平铺**（50,561 条记录，76 种 opcode 实际出现）；唯一“失败”是标签表尾的终止空条目造成的伪段，非代码。
- 南方版 sce（GPT 汉化版，头部与代码区长度与原版一致）：同表平铺 959/960（同一伪段除外），文本记录同为 27,492 条——**格式与签名表跨版本成立**。
- 对白导出与池下标、场景、说话人全部对齐（如 001-000 开场与池 92–149 号串逐条对应）。

## 7. 未定项

- 0x92：签名在解释器中为 (E) 或无操作数两种读法均有可能；两作 sce 中均未出现，不影响解析。
- 0xD6 文本块在本样本 0 次出现，其条目语法仅据解释器伪代码，未经数据验证；条目 0xD3 行尾是否另有 u16（与独立 D3 记录的保留字段类比）未定。
- 0x2D–0x32 的语义（条件 Gosub）为据同族结构推断，语法已实测。
- 0xAC 的 (x, y) 轴义未定（handler 与共现已实测，见 §4 表）；0x8E/0x8F 的标志位（0/1）区别未定。
- 子系统 7 的确切身份（过渡命令队列/场景状态机）未定名，不影响 §4 中各 op 的脚本级语义。
- 0x80 等 CG 族命令的 (E,4) 中 E 的精确含义未逐一命名；签名均已实测。
- 本格式在 macho 等同引擎他作上的适用性为推断（引擎同一性已由 62 个 RTTI 类名验证，sce 布局待其数据文件实测）。
